# 待办池状态

给需求方一个 30 秒能读完的全局视图。**只读不写**，不做任何修改，不实施任何任务。

---

## 执行

0. 若 `.claude/backlog.md` 不存在，提示需求方先跑 `/task:init`，然后结束。
1. 读 `.claude/backlog.md`、`.claude/dev-plan.md`、`.claude/dev-progress.md`。
2. 统计并输出下面的报告。
3. **自动循环信息**（若有）：`.claude/auto/current` 存在 → 报告正在跑的 worker 任务与开工时长；`.claude/auto/run.log` 最近 5 行；`.claude/auto/STOP` 是否存在；`.claude/inbox/*.md` 未合并投递数。backlog 的「待决策」表**逐条列出问题和选项** —— 这是需求方最需要处理的队列，放在报告最前面。

**关键要求：检查阻塞任务的阻塞是否已实际解除。** 例如某任务依赖 `T-005`，而 `T-005` 已在 `dev-progress.md` 里完成 —— 那这个阻塞是过期的，必须在报告里标出来，并提示需求方可以解除。这是这个 skill 最有价值的部分，不要跳过。

## 输出格式

```
## 待办池 · 2026-09-03

**进行中**：T-009 修复配额并发扣减（开工 09-03，阶段：实施中）
**待验证**：T-007 知识库前端页面 —— 等你确认

| 优先级 | 待开始 | 阻塞 | 合计 |
|--------|-------|------|------|
| P0     | 0     | 0    | 0    |
| P1     | 1     | 1    | 2    |
| P2     | 4     | 1    | 5    |
| P3     | 2     | 0    | 2    |

**阻塞明细**
- T-001（P1）← H-025 部署 turnkey RAG 服务到内网
- T-006（P2）← 缺 vendor 映射信息

**⚠️ 阻塞可解除**
- T-012 依赖的 T-005 已于 09-02 完成，可改回「待开始」

**已交付**：本月 3 项，打回 0 次

**建议下一步**：T-002（补 cache ratio 边界测试，零依赖小改动）
```

若待办池为空：直接说空了，列出阻塞事项，提示用 `/task:add` 录需求。不要建议自己想出来的任务。
