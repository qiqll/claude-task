# 待办池状态

给需求方一个 30 秒能读完的全局视图。**只读不写**，不做任何修改，不实施任何任务。

**输入：** $ARGUMENTS
- 为空 → 走下面「执行」，输出全局视图。
- 匹配 `^[Tt]-[0-9]{1,3}$` → 规范成大写 `T-` 加补零到 3 位的数字（`t-11` → `T-011`），走文末「单任务时间线」，**不输出**全局视图。
- 其他内容 → 先回一句「用法：`/task:status` 看全局，`/task:status T-0NN` 看单个任务的时间线」，再照常输出全局视图（与以前忽略参数的行为兼容）。

---

## 执行

0. 若 `.claude/backlog.md` 不存在，提示需求方先跑 `/task:init`，然后结束。
1. 读 `.claude/backlog.md`、`.claude/dev-plan.md`、`.claude/dev-progress.md`。
2. 统计并输出下面的报告。
3. **自动循环信息**（若有）：`.claude/auto/current` 存在 → 报告正在跑的 worker 任务与开工时长；`.claude/auto/run.log` 最近 5 行；`.claude/auto/STOP` 是否存在；`.claude/inbox/*.md` 未合并投递数。backlog 的「待决策」表**逐条列出问题和选项** —— 这是需求方最需要处理的队列，放在报告最前面。
   **待验证清单**紧随其后：每条一行写 ID、标题、已挂天数（今天 − 备注 `待验证起`，没有就写「起始日未记录」）、`怎么验`、到期日（`待验证起` + backlog「待验证超时」天数，缺省 7；`0` = 关闭时不写）；有 `超时预告` 的标「明天默认通过」；备注含 `默认通过：否` / `⚠ 高风险区域改动` / `⚠ 测试有改动` 的标「需你亲自看，不会默认通过」。清单末尾给一行批量命令：`qtask --pass`（全部通过）/ `qtask --pass --except T-x`。只读：不在这里补起始日、不预告、不关闭（那是 loop 调度员和 /task:next 的到期检查）。

4. **人工度量**（口径与面板指标区一致；`run.log` 不存在或没有任何「结束行」时三项都写 `—`）。「结束行」指 `run.log` 中第二列为任务 ID、第三列形如 `<RESULT>→<最终状态>` 的行（`RESULT` 后可带括号说明，如 `FAILED（超时）→阻塞`）：
   - **人工介入**：最终状态为 `待决策` / `阻塞` 的结束行数 + `REJECTED` 行数；某任务没有 `REJECTED` 行（旧日志）时，改计它带「打回」的 `DONE→` 行数，再加上「当前状态为 `打回` 且 run.log 里交付过」的 1 次。只统计 worker 运行结果与合并进循环的答复。
   - **决策等待**：每条 `→待决策` 结束行到该任务之后第一条 `DECIDED` 行（没有 `DECIDED` 时取之后第一条 `DISPATCH`，含排队时间）的时长，取中位数；还没答复的不计入，但在待决策清单里写出已挂起多久。
   - **回滚率**：`ROLLBACK` 行数（真正回退到开工点的 FAILED；没回滚的不算）/ 结束行总数，并附 `git for-each-ref refs/auto-failed/ | wc -l` 的留存 ref 数作对照（两者不等时照实写出，不要猜原因）。

**关键要求：检查阻塞任务的阻塞是否已实际解除。** 例如某任务依赖 `T-005`，而 `T-005` 已在 `dev-progress.md` 里完成 —— 那这个阻塞是过期的，必须在报告里标出来，并提示需求方可以解除。这是这个 skill 最有价值的部分，不要跳过。


## 单任务时间线（`/task:status T-0NN`）

回答「这个任务从录入到现在经历了什么」。同样**只读**。下面 `$ID` 指规范化后的任务 ID；ID 匹配一律带边界（`T-011` 不能命中 `T-0110`），grep 用 `-E '$ID([^0-9]|$)'`。**下面命令里的 `$ID` 一律先替换成字面 ID（如 `T-011`）再执行，不要定义 shell 变量**——命令多用单引号，`$ID` 在单引号里不会展开，只会被当成行尾锚点而静默查空。

0. 若 `.claude/backlog.md` 不存在，提示先跑 `/task:init`，结束。
1. **定位任务**：
   - backlog 中首列为 `$ID` 的行（`grep -nE '^\| $ID \|' .claude/backlog.md`，可能同时出现在优先级表和「待决策」表）→ 取任务、模块、状态、依赖、备注。
   - `dev-progress.md` 中的 `### $ID ` 记录 → 取完成日期、结论、Commits、遗留。
   - 两处都没有 → 输出「未找到 $ID：backlog 和 dev-progress 里都没有这个任务（现有 ID 范围 T-001 到 backlog「ID 分配规则」里「下一个可用 ID」减 1）」，若第 2 步的 run.log / commit 里仍有它的痕迹（先照常查一遍再下结论），再补一句「但在 <run.log / commit> 里有记录，可能已被删除或改号」。结束，不输出空时间线。
2. **收集事件**（每条记为 `时间 | 类型 | 内容`；拿不到的来源跳过，在「来源」行注明）：
   - **自动循环流水**：`grep -E '\| $ID \|' .claude/auto/run.log`，每行一条 —— `DISPATCH`（类型「派发」，带 nonce）、`<RESULT>→<最终状态>`（类型「交付」/「失败」/「待决策」等，带 commits 数、耗时、衍生数、一句话）、`WATCHDOG`（类型「看门狗」）。`run.log` 不入库，不存在就记「无 run.log（未在本工作区跑过自动循环）」。
   - **本分支提交**：`git log -E --grep='$ID([^0-9]|$)' --date=format:'%Y-%m-%d %H:%M:%S' --format='%ad %h %s' HEAD`（用作者时间，rebase / amend 不改它）；再补上 dev-progress 记录 `Commits：` 里列出、但 message 不含 ID 的哈希（`git show -s` 同样的 `--date` / `--format`；解析失败记一条「`<hash>`（已不在仓库）」，继续往下走）。每个提交一条：短哈希 + 原始 subject（保留 `docs(task):` 等前缀，截到 60 字）。`docs(task):` 开头的是调度员记账（录入 / 开工 / 交付 / 归档），类型写「记账」，其余写「提交」。
   - **失败留存**：`git for-each-ref --format='%(refname:short)' "refs/auto-failed/$ID-*"`；每个 ref 一条「失败留存 <ref>」，时间取该 ref 顶端提交时间，并用 `git log --format='%h %s' HEAD..<ref>` 附上不在当前分支的提交哈希。
   - **决策与验收**：backlog 备注里的「需求方决策（日期）：…」「自动交付（日期）：…」「自动失败×N：…」「打回」；「待决策」表中 `$ID` 行（挂起时间 + 问题）；`.claude/inbox/.merged/` 与 `.claude/inbox/` 下第一个 `---` 块里有 `ref: $ID` 的文件（时间取 `created:`，内容取正文首行，截到 60 字；后者标「（未合并）」）。
   - **人工阻塞**：backlog「人工阻塞事项」表中「阻塞的任务」列含 `$ID` 的 `H-NNN` 行，记一条「人工阻塞 H-NNN：描述 · 状态」（状态里有日期就用该日期，否则无时间、排在末尾）。
   - **完成归档**：dev-progress 记录的「完成：日期」，一条「归档」，内容写记录里的「关闭方式」（旧记录没有就写「需求方确认」）；有「重开：日期」再记一条「重开」。run.log 的 `TIMEOUT_PASS` 行类型写「超时通过」。
3. **衍生关系**：
   - 子任务：backlog 与 dev-progress 中备注 / 正文含「衍生自 $ID」的任务，加上 dev-progress 本任务「遗留：」里 `→ T-0NN` 指向的任务。列 ID、标题、当前状态（已归档的写「已完成」）。
   - 父任务：本任务备注里有「衍生自 T-0XX」；或反向查——别的任务在 dev-progress「遗留：」或 backlog 备注里写了 `→ $ID`（带边界：`→ $ID([^0-9]|$)`），那个任务就是父任务。任务归档后 backlog 行已删、dev-progress 不写来源，**只能靠反向查**，不要漏。
   - 都没有 → 写「衍生任务：无」。这一行**必须输出**，不能省略。
4. **排序与去重**：按时间升序。只有日期没有时刻的事件（备注里的决策日期、归档日期）排在同一天带时刻的事件之后，时刻栏写 `--:--`。同一个提交只出现一次（`git log` 与 Commits 列表重复时合并）。同一次决策 / 打回在 inbox 文件和 backlog 备注里各有一份时只保留 inbox 那条（`created:` 带时刻）；只有备注、没有时刻时，用对应 `docs(task): 合并投递` 提交的时间定位，避免排到它引发的重新派发之后。事件超过 40 条时，`WATCHDOG` 合并为一行「看门狗 N 次（首 … 末 …）」。
