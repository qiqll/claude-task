# 待验证规则（loop 调度员与 /task:next 共用）

目标：人只看真正需要人看的交付。机器能判定的直接关；人没空看的到期默认通过；关掉的随时能打回重开。所有自动关闭都在 `dev-progress.md` 写明关闭方式，可追溯。

**超时配置**：backlog 里 `**待验证超时：** N 天`（缺省 7；`0` = 关闭默认通过，本文「到期检查」整节跳过）。

**循环是否在跑**：`.claude/auto/run.log` 里最后一条 `| START |` / `| STOP |` 行是 `START`（`grep -E '\| (START|STOP) \|' .claude/auto/run.log | tail -1`；与 `qtask`、面板同口径；循环空闲等任务时没有 `current`，但仍算在跑）。只看这两种行：`/task:next` 也会往 run.log 写 `TIMEOUT_PASS`，不能拿最后一行判断。在跑时 backlog / dev-progress 只由调度员写，`/task:next` 只报告、不执行本文的写操作。

---

## 1. 进入待验证时写的子句

任务进入 `待验证`（loop C4 / `/task:next` Step 5）时，备注里**先删掉**旧的 `待验证起：` `超时预告：` `怎么验：` 子句（打回重做后再交付，旧日期不能沿用），再追加：

- `待验证起：YYYY-MM-DD`（今天）
- `怎么验：<≤3 步>`：优先一条可直接运行的命令或一个 URL，其次是具体操作和预期结果。来源是 worker 报告的 `VERIFY`（loop）或你自己写的（`/task:next`）。

`怎么验` 写在表格单元格里，**格式硬规则**：不得出现 `;` `；` 和 ` · `（面板按它们拆子句），步骤之间用 `→` 连接；命令放反引号里；**任何** `|`（命令里、正文里都算）一律写成 `\|`，否则会切开表格行；不换行。例：`怎么验：跑 \`bun test hooks\` 看 62 项通过 → /task-dash 展开一条待验证任务，有「怎么验」一栏`。

## 2. 自动验收（只在 loop C1 全过之后判定；`/task:next` 没有这一步，交付一律进待验证）

**公共条件**（全部满足才继续往下判）：

- 测试检查结果是 `PASS`（`PASS_PREEXISTING` 不行）。
- `check_test_weakening.sh` 退出码 0 且**没有任何 WARN**（只改测试的 diff 最容易把测试改弱，有理由的 WARN 也不行）。
- 未命中高风险区域；本轮没往「待决策」表加行；报告 `ASSUMPTIONS` 为 `—`。

**再满足下面任一条**，就免人工验收：

- **(a) 只动测试**：`git diff --name-only <start> HEAD` 的每个路径都匹配 `(^|/)(tests?|__tests__)/`、`_test\.`、`\.test\.`、`\.spec\.`、`(^|/)test_[^/]*$`、`conftest\.py$`，且没有 `.yaml` / `.yml` / `.json` 文件（测试目录里的它们常是契约或配置）。文档、README、CHANGELOG 不算：它们是给人看的。
- **(b) 录入时标了免验**：备注含 `验收方式：自动`，优先级是 P2 / P3，报告 `ACCEPTANCE` 来源是 `backlog`，**并且**备注里的 `验收：` 子句不带「AI 拟」标记——验收标准必须是需求方给的（或需求方改过、去掉了标记），免验才由机器说了算。验收标准是 AI 拟的，就照常进待验证（到期仍会默认通过）。

命中 → 结论 `已完成`，按第 4 节归档，关闭方式 `自动验收（规则 a）` / `自动验收（规则 b）`；`run.log` 结束行写 `DONE→已完成（自动验收）`；简报照发，但不发通知。不命中 → 照常进 `待验证`。

## 3. 到期检查

**谁跑、何时跑**：loop 调度员在 B3 合并 inbox 之后、挑任务之前（心跳发现无事可做时也跑一次）；`/task:next` 在 Step 1 开头（仅当循环不在跑）。`.claude/auto/verify-checked` 内容等于今天就跳过（loop 跑完后写入今天日期；`/task:next` 不看也不写这个文件，重复跑也没有副作用）。

**先避让未合并的答复**：`.claude/inbox/*.md` 里有 `ref: T-0NN` 的未合并文件 → 该任务本次跳过（loop 已在 B3 合并过，不会遇到；`/task:next` 遇到时提示需求方「T-0NN 有未合并的答复，开 /task:loop 或手动处理」）。

对每个 `待验证` 任务按顺序判：

1. **补起始日**：没有 `待验证起` → 推断：
   `git log -1 --format=%as -E --grep='^docs\(task\): T-0NN 自动交付'`；
   为空则取 `git log --format='%as %s' -E --grep='T-0NN([^0-9]|$)' | grep -v ' docs(task):' | head -1` 的日期；
   仍为空记今天。写成 `待验证起：YYYY-MM-DD（推断）`。推断偏晚是保守方向（晚关不早关）。
2. **不默认通过的**：备注含 `⚠ 高风险区域改动`、`⚠ 测试有改动` 或 `默认通过：否` → 不预告、不关闭。到期那天在本次检查的输出和通知里提醒一次（去重键 `VERIFY-HOLD:T-0NN:<待验证起>`），之后只在 `/task:status` 里列出。
3. **预告**：已挂天数 `d = 今天 - 待验证起` ≥ N-1，且没有 `超时预告` → 写 `超时预告：YYYY-MM-DD HH:MM`（现在），记入本次预告列表。存量任务第一次检查时往往已超期，同样先预告，**不跳过预告直接关**。
4. **关闭**：有 `超时预告`，距预告时刻已满 24 小时（只有日期的旧写法按当天 00:00 算），且 d ≥ N → 先做证据检查：
   - 收集交付提交：备注「自动交付…commits …」里的 SHA，加上 `git log --format='%H %s' -E --grep='T-0NN([^0-9]|$)' | grep -v ' docs(task):'` 查到的提交（每次都查，不管第 1 步有没有跑）。
   - 一个都没有 → 证据「无法检查」，照常关闭（`/task:next` 时代交付的存量多半如此）。
   - 有：至少一个满足 `git merge-base --is-ancestor <sha> HEAD`，且 `git log -1 --format=%h --grep='This reverts commit <完整 sha>'` 为空 → 证据「提交在当前分支」，关闭。
   - 有但全都不可达或已被 revert → 不关闭，挂待决策「T-0NN 的交付提交已不在当前分支或已被 revert」，选项：A. 打回重做（推荐）；B. 取消；C. 仍按通过关闭。
   - 关闭 = 按第 4 节归档，关闭方式 `超时默认通过（d 天无人打回）`；起始日是推断的再加 `· 存量`；证据写进记录。`run.log` 追加 `<时间> | T-0NN | TIMEOUT_PASS | 待验证 d 天`。
5. **排序（只影响先看哪条，不影响关不关）**：对预告列表里每个任务跑 `bash ${CLAUDE_PLUGIN_ROOT}/skills/loop/verify_signals.sh <项目根> T-0NN`（只读，纯 git 机械判定），按 `TIER` 写备注子句（覆盖旧的同名子句；用「、」分隔，不用 ` · `）：
   - `TIER 1` → `后续迹象：无，用户可见改动，建议先看`（`VISIBLE unknown` 时写「无，查不到交付提交，建议先看」）
   - `TIER 2` → `后续迹象：无`
   - `TIER 3` → `后续迹象：✓ <LATER 里的 ID> 后来改过同批文件、<DOWNSTREAM 里的 ID> 依赖它已交付`（没有的那半句省掉）
   预告列表按 TIER 1 → 2 → 3 排，同档按已挂天数从多到少。
6. **通知与提交**：预告列表非空 → 发**一条**通知（去重键 `VERIFY-DUE:<今天>`）：`N 条待验证明天默认通过，先看 T-1 T-2（无使用迹象），其余 T-5✓ T-6✓…，有问题 qtask -d T-x 打回：原因`（≤100 字放不下就只列先看的，其余写「等 N 条」）。本次输出里按同样顺序逐条列出 ID、标题、`怎么验`、迹象。通知发没发出去（SKIP / FAIL / 关闭）都不影响：预告也写进本次输出，面板任务卡片上能看到到期日。有改动就 commit `docs(task): 待验证到期检查 预告 <ID…> 关闭 <ID…>`，只 add backlog / dev-progress（以及待决策改动所在的 backlog）。

## 4. 归档（所有关闭方式共用）

1. 从 `backlog.md` 删除该行。
2. `dev-progress.md` 按记录格式追加一条（倒序，加在最上方），`**关闭方式：**` 写 `需求方确认` / `自动验收（规则 a|b）` / `超时默认通过（d 天无人打回）[· 存量]`；超时关闭的再写 `**证据：** 提交在当前分支 / 无法检查`。更新顶部统计。
3. loop 里由 C4 / 到期检查的 commit 一起提交；`/task:next` 自己 commit。

**落盘中断的恢复**：loop `phase=accepted` 续跑时，「backlog 已含结论」包括两种情况：backlog 行状态已是结论，或者结论是 `已完成` 且 backlog 已无该行、`dev-progress.md` 已有 `### T-0NN` 记录。两种情况都不要重复归档。

## 5. 答复的处理（loop B3 合并 `type: decision`；`/task:next` 收到需求方口头答复）

| 任务当前状态 | 答复 | 处理 |
|---|---|---|
| `待验证` | 通过 / OK 类 | 第 4 节归档，关闭方式 `需求方确认` |
| `待验证` | 打回类 | 状态 `打回`，备注追加「打回（日期）：<意见>」，删 `超时预告`；`run.log` 追加 `REJECTED` |
| 已归档（backlog 无此行，dev-progress 有 `### T-0NN`） | 打回类 | **重开**：按 dev-progress 记录的优先级 / 模块，把行加回 backlog 对应优先级表，状态 `打回`，备注「重开（日期）：原关闭方式 <…>；打回：<意见>」；在 dev-progress 该记录末尾追加 `**重开：** 日期`；顶部统计打回 +1；`run.log` 追加 `REJECTED` |
| `待验证` | 「别默认通过 / 我要亲自看」类 | 备注加 `默认通过：否`，删 `超时预告`，状态不变 |
| 已归档 / 不是待验证 | 通过类（如 `qtask --pass` 快照过期） | 不改状态，处理完照常移进 `.merged/`，在合并提交的 message 里写「T-0NN 已不在待验证，跳过」 |

批量答复（`qtask --pass`、`-d T-1,T-2`）每个 ID 一个文件，逐个按上表处理，合并成一次 commit。
